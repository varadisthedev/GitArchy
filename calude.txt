How it behaves

- Database fallback: DATABASE_BACKEND=memory is the only way to get the in-memory store. With astra selected, the app refuses to start if Astra is unreachable, and APP_ENV=production rejects memory outright.
- Git storage: Git runs through the real CLI with commits built from a temporary index and no working tree. Live repositories need a persistent disk. R2 only holds verified bundle exports and uploads, and there is no automatic restore.
- Not implemented: git clone and git push over HTTP.
- Logout: it really revokes the token (checked on every request).
- Avatars: the server uploads them to Cloudinary, so the browser never gets a signature. This is a deviation from "generate upload parameters"; the secret never leaves the server.
- Limits that will matter when you scale:
  - Rate-limit counters are per process.
  - The repo write lock is per process.
  - Worker connections are held in one API instance.
  - Use one API instance until you add shared storage.

Things I found along the way

- Cassandra driver on Python 3.12+: it needs the pyasyncore package to import at all. I added it to requirements.txt.
- Windows repo deletion: deleting a repo failed because Git's object files are read-only. Fixed.
- Deleting a file in a bare repo: update-index --force-remove doesn't work there. It now uses --index-info.
- 500 responses: they were missing X-Request-ID. Fixed.
- Colab worker: the worker needs numpy for the MLlib tasks, and a stale PYSPARK_PYTHON on this machine broke executors. The worker now forces its own interpreter.
- Spark job duration: K-Means took about 130 s and logistic regression about 110 s on tiny data locally. The 900 s job limit covers it.
